# 小账本（管理员）

入口在「代购管理」下方，同一控制台内打开 `/admin/ledger`。

## 使用与边界

- 收支流水：手动收入、支出、非现金赠送额度，支持编辑、再记一笔、作废、筛选、分页及 CSV 导出。作废保留原记录与变更历史，不可恢复；需要重记时使用「再记一笔」。
- 汇总跟随筛选，各币种独立，赠送不算现金支出；现金收支差额不是利润。金额使用字符串传输与 PostgreSQL NUMERIC，最多六位小数，不经浮点计算。
- 续费提醒：记录域名、服务器和其他资源的服务商、准确到期时间、预计费用、HTTPS 管理入口及备注。可标记不再续费，记录仍可查。
- 建资源不自动记支出。新增支出时可同时建资源。续费可同时记支出，或仅更新日期。新到期时间须晚于原时间；日期录错用「编辑」修正。
- 记账、资源、历史均为独立 `ledger_*` 表，不读取或改动网关计费、余额、代购订单或上游账号；没有自动扣款、续费、余额查询。
- 仅使用现有真实管理员鉴权，不提供测试登录或权限绕过。

## 提醒

默认提前 30、7、1 天，可在「提醒设置」修改。按应用配置时区的自然日计算，实际到期时进入「已到期」阶段。不再续费的资源不提醒。

页面关闭仍由服务端运行提醒任务。邮件默认关闭，管理员手动开启并填写最多五个收件邮箱后，复用系统 SMTP；无需另设密码。每天配置时区的 09:00 后，每 15 分钟检查一次。每邮箱每天最多一封摘要，同一资源、同一到期时刻、同一提醒阶段去重。应用停机期间不保证准点提醒，重启后发送当前适用阶段。

发送前在 PostgreSQL 持久化领取当日邮件，避免多实例重复发送；成功后记录阶段去重。失败或结果未确认不在当天重发，次日重试当前适用阶段。SMTP 发送与数据库提交不能构成一个原子事务，因此极端情况下邮件已送达但状态未落库，次日可能再次提醒。近期发送状态可在提醒设置中查看。

## 安全与一致性

写操作使用 UUID 幂等编号，操作结果与业务数据同一事务提交；同编号、同请求重试返回原结果，异内容冲突。更新使用版本号避免并发覆盖。流水、资源变更记录操作人和修改前后快照，页面显示最近 100 次历史。

续费与记支出、建资源与记支出均为同一事务，失败全部回滚。CSV 最多导出一万条，可通过筛选分批导出；用户输入单元格转义公式前缀。管理链接只允许 HTTPS，不存登录凭据、不由服务器请求外链。账本响应禁止缓存。

部署自动执行新增迁移 `246_admin_ledger.sql`，不修改既有业务表。回退应用版本可保留新表及数据，不要为回滚删除账本表。数据管理备份需覆盖这些表；现有按全库备份的方案自然包含。
