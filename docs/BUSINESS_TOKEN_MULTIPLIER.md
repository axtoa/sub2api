# Business 分支：Token 消耗倍率

管理后台 → 分组管理 → 新建或编辑分组 → **Token 消耗倍率**。
默认 `1`，允许 `1–100`，API 最多支持四位小数（与数据库精度一致）；管理界面按 0.1 步进。旧分组升级后保持 `1`；复制分组会保留设置。

## 计费口径

- 每次请求先按原规则计算费用，再将用户应付金额乘以该倍率。原有分组价格倍率、用户专属价格、缓存价格和媒体价格规则仍然有效。
- 用户余额、套餐用量、API Key 额度和金额限额使用放大后的费用。上游账户额度、原始费用与实际 Token 统计不乘这个倍率。
- 使用日志及用户统计中的各类 Token 数分别乘倍率并向上取整；金额直接乘倍率，不使用取整后的 Token 重新定价。例如原始输入 101、输出 31，倍率 1.5 时记录为 152、47，费用为原用户应付费用的 1.5 倍。
- 数据库保留请求的倍率快照和原始 Token 数。管理员日志 API 的 `actual_*_tokens` 是原始值；原有 Token 字段是计费统计值。费用明细展示该次请求的倍率，修改设置不会追溯重算历史日志。
- 上游请求、模型输出和协议响应中的 `usage` 保留真实数据；这里放大的是站内计费统计，不是模型实际生成量。无 Token 的按次、图片、视频调用只放大原本的应付费用，不虚构 Token。
- 免费调用仍免费；Simple 模式保持原行为。现有 Live 会话没有 Token/费用计量，本功能不为它新增计费。
- 异步批量图片在提交时固定倍率，同时放大冻结额和结算价。任务提交后修改分组设置，不影响该任务的结算或退款；升级前的任务继续使用原快照。

## 部署与回退

新站部署 `business` 分支，并使用**独立 PostgreSQL 数据库及独立 Redis 实例或隔离命名空间**。仅切换代码分支不能隔离分组配置、余额、认证缓存及后台任务，两个站不要共用这些运行数据。

启动时执行迁移 `242_group_token_usage_multiplier.sql`，增加分组倍率、日志原始用量字段和批量图片倍率快照。迁移不重算历史用量；日志约束使用 `NOT VALID` 避免扫描历史大表，新写入仍受约束。认证缓存版本同步升级，旧缓存会回源重建。

上线先保留倍率 `1`，用测试分组设置 `1.5` 或 `2` 核对一笔普通调用、一笔流式调用及套餐扣费后再启用。恢复某分组的原扣费速度只需将倍率设为 `1`；已经提交的批量任务仍按提交时的快照结算。代码回退前应先停止接收任务、完成在途结算并备份数据库，不能假设旧版本会识别新增的计费统计口径。

## 验证记录

已增加网关扣费回归测试，覆盖余额、套餐、免费调用、Simple 模式、流式/非流式、API Key 限额、上游账户额度不变、原始用量保留、小数取整，以及批量任务快照和重复结算。认证缓存往返及分组复制包含倍率验证。

原始版本存在与本功能无关的测试失败：前端 9 项（平台枚举、Pinia 测试初始化等），后端 15 项调度生命周期测试（硬编码平台数量）。均已在基线版本复现；后端基线测试仅重命名了一个与生产代码冲突的测试辅助函数以便编译。本分支也包含该辅助函数重命名。

本地未提供运行中的 PostgreSQL/Docker，尚未执行真实数据库迁移和端到端扣费；数据库测试使用仓储测试与 SQL mock，不能替代部署环境的验证。
