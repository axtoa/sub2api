# Best AI 质量监控

入口：管理员侧边栏「仪表盘」下方的「质量监控」。普通用户无法访问页面或 API。

## 第一版的边界

- 首次进入自动同步全部未删除账号；后续刷新只更新检测结果，新增账号通过「同步账号」手动补入。停用监控或暂不支持检测的账号仍展示，删除的账号不展示。
- 一个账号一张卡片，多个模型在卡片或详情中切换，多分组账号不会重复计数。统一使用紧凑卡片，点击卡片展开详情；卡片显示当前检测模型、最近 48 次探测、24h 可用率、具体失败原因和执行状态。
- 新账号优先使用最近成功调用的具体文本模型，否则选取本地模型映射中的一个具体文本模型，再回退到平台默认测试模型。每个新账号只初始化一个检测模型；已有模型及其独立设置保留。不会扫描上游模型接口；通配符、媒体模型和不支持的类型不会自动发送检测。可在账号详情的「单独设置」中增加具体模型。
- 重复同步只补充新账号及没有检测目标的账号，不重置关闭状态、独立配置、历史或频次。旧版本全部模型都关闭的账号，首次同步时保留账号关闭状态。
- 支持 OpenAI API Key / OAuth、Anthropic API Key / OAuth / setup-token 文本账号。暂不支持 Gemini、媒体模型、通配符目标、凭据影子和需要创建远端任务的 Agent Identity 账号。
- 复用账号测试的认证、代理、模型映射和协议选择，固定账号，不经过故障转移。质量检测专用上下文禁止原有测试接口的错误状态、429 状态和额度快照写入。
- **只观察，不自动禁用或恢复账号，不调整优先级、分组、价格和用户账单。** 实际请求会消耗上游额度；检测预算独立记录，不写用户消费日志。
- 测活只要求有效文本回复并正常结束，不要求固定问候或 JSON。能力抽检默认每轮一道随机参数题，降低路径题规模与记录数量，仅比较最终整数。可在检测设置编辑最多 12 道自定义整数答案题（按模型匹配），不匹配时使用内置题库。格式不明单独标为检测故障，不计答错。标准答案及题库变更纳入配置校验与历史指纹。不调用付费裁判模型，不执行回答中的代码。
- 单轮未达门槛显示「疑似异常」；上一轮相同配置也未达门槛时显示「持续异常」。这只是小样本任务表现，**不能证明模型身份，也不能保证识别所有能力降级**。建议先以可信正常账号校准，再看相同模型、参数的历史变化。
- 超时、截断、限流、预算不足和请求参数被拒绝记为未完成，不判答错。历史保留参数标识、题目、标准答案、回答、实际报告模型、用量和原因。

## 默认频次与成本

| 项目 | 默认值 | 请求数 |
| --- | --- | --- |
| 补充测活 | 每 30 分钟 | 每轮 1 次；近 15 分钟有真实成功且无采集到的上游错误则跳过 |
| 能力检查 | 每 12 小时 | 每轮 1 题，每题 1 次 |
| 缓存验证 | 仅手动 | 每轮 2–3 次，32 KB 稳定前缀；后续请求换问题后缀 |
| 异常复测 | 追加 1 轮，间隔 5 分钟 | 受同一预算约束 |
| 输出上限 | 每次 2048 token | 可在 256–8192 之间调整 |
| 每日预算 | 1000 次请求、200 万 token | 按服务端配置时区零点换日 |

这些默认值只作用于新配置，已有频次和题数保留；可在设置恢复默认值后保存以启用轻量配置。以上均可在「检测设置」修改；每个账号模型也可「单独设置」，或恢复继承全局值。全局、账号、模型的自动检测开关只影响自动任务。手动检测不受自动开关、自动频次、自动预算和账号调度冷却限制，但仍需真实管理员鉴权、受支持的账号类型、并发槽和请求超时。已经发往上游的请求无法撤回。

新默认单目标最多约 50 次常规请求/日（48 次测活 + 2 次能力题，不含复测），真实调用会减少补充测活。模型推理成本、缓存验证的长输入成本不能只看请求数。页面显示每日计划估算和实际预算占用，不承诺固定人民币成本。

每次请求先以 UTF-8 字节上界、系统提示、最大输出及额外开销预留 token，再根据完整上游报告结算；用量缺失、格式不合法、响应中断或进程崩溃会保留保守预留量，不按零消耗处理。上游实际超报仍会计入，因此预算是保守调度阀门，而不是第三方账单的绝对封顶承诺。降低预算不清空已用量。手动请求和 token 单独统计，不扣自动预算，没有自动预算上限保护，请自行控制手动检测次数。

## 缓存与可用性口径

- 卡片缓存比例仅采用主动验证的上游报告值，不采用站内 usage_logs 的计费缓存调整。
- 主动「缓存验证」直接读取上游原始缓存字段。预热后的请求报告缓存读取大于零才显示「观察到命中」。
- 完整回答但未命中显示「未观察到命中」；没有缓存字段显示「无法判断」。缓存写入传播时间、模型缓存门槛、路由以及上游不透传字段均可能影响结果，不能据此认定缓存故障。
- 缓存输入占比为验证请求的缓存读取 token / 输入 token，预热请求不计入。Anthropic 分母包含非缓存输入、缓存读取及写入；OpenAI 分母为上游报告的总输入。用量字段缺失或不一致不显示为 0% 或 100%。
- 真实调用失败数来自运维上游错误日志，受日志开关、采样和保留范围影响，不视为完整请求成功率。近期可用性条仅记录检测任务（含明确标记的真实流量跳过），不伪造流量。
- 24h 探测可用率使用最近 24 小时已完成可用性检测的成功 /（成功 + 失败），未知和未完成不计入分母；没有有效记录显示「—」。后端保留最多 180 次，紧凑卡片只显示最近 48 次，不足的格子留灰。
- 能力详情展示精确题目、本地标准答案与解法、原始回答、判定、请求参数及上游报告模型。原始回答仅按文本渲染，不能执行代码；上游自报模型不是身份验证。

## 持久化与升级

- 迁移 `244_quality_monitor.sql` 与 `245_quality_monitor_accounts.sql` 仅新增或调整 `quality_monitor_*` 表及索引，不改原账号、用量和订单数据。
- 队列持久化。自动任务去重，手动每次点击都生成独立任务，不因已有排队任务被丢弃；同一账号同时最多一个执行任务，跨进程锁保护抢占。每进程最多两个任务执行，数据库短事务与账号级检查保证同一账号跨模型不并行；手动队列优先，同级测活优先；自动并发满延后 5 分钟，手动等待可用并发槽至请求超时，不突破业务并发上限。
- 手动任务不改自动计划的下次执行时间，也不追加自动复测。修改检测题目或请求参数会停止当前轮；单纯调整自动开关、预算和频次不影响已受理的手动任务（频次不参与实际题目或请求参数变化时）。
- 服务重启后过期执行任务标为「执行中断」，不自动重放可能已经扣费的请求。完成时使用版本校验，旧任务不能覆盖新设置的调度时间；每条请求前复核目标、设置和账号路径。
- 最近 24 小时的已完成检测全部保留，保证 24h 探测可用率的分母完整；更早的历史只保留每目标每类型最近 180 轮，且不超过 30 天，按小时分批清理。卡片接口最多返回 180 条可用性历史，并另保留最近一次有效能力结果；失败的新尝试不覆盖它。生成的参考答案只在请求完成后保存在本站，不发给上游。
- 上线无需配置新依赖；上线前仍应执行数据库备份，并用小范围账号观察默认门槛。回滚旧程序时保留新增表即可，勿删除业务表。

## 本轮简化与隔离

- 工具栏按当前筛选账号的当前所选模型批量运行，100 项一批提交，任务进度使用独立管理员汇总接口；每次点击独立入队。失败的提交不自动重发，避免重复付费。账号管理原测试窗口增加能力抽检入口，不修改原连接测试行为。
- 自动测活可复用最近 15 分钟相同模型的成功定时连接测试（且没有随后定时失败或已采集到的上游错误），原定时测试及可选自动恢复功能保持原行为。
- 增加 Chat Completions 最终 message 文本及 `[DONE]` 结束兼容；保留截断、内容过滤与错误事件，不能因收到结束标记将失败改判为成功。错误参数只存固定白名单，不存原始上游错误正文、URL 或凭据。
- Codex OAuth 沿用连接测试的原生输出限制，不发送不兼容的 `max_output_tokens`；预算按至少 32768 输出 token 保守预留，并按实际报告结算。界面明确标注原生限制；API Key 通道继续强制配置的输出上限。请求仍有 120 秒超时、1 MB 流读取上限和 32000 字符证据上限，不能保证第三方实际计费绝对封顶。
- 不完整能力检测会按配置有限复测，忙碌或暂不可调度的账号 5 分钟后再试；原有用户请求转发、账单、速刷和故障转移逻辑没有修改。
- 新增能力题库存于已有质量监控 settings JSON，不新增业务表。测试数据只存在隔离的本机预览数据库和临时目录，不进入仓库。


## 独立渠道检验

质量监控工具栏新增“渠道检验”。选择现有账号模型，手动提交独立、持久化的 `inspection` 任务；不修改自动检测计划。快速方案默认六项、最多 9 次请求；完整方案默认九项、最多 19 次请求。可自行勾选项目，开始前展示请求数、输出限制及长输入提示。实际费用取决于模型及上游计费，不给固定金额承诺。所有请求固定账号，沿用其模型映射、代理、认证和 TLS 配置；与现有检测共用账号并发槽，手动用量单独记录，不写业务消费日志。

| 项目 | 检验方式 |
| --- | --- |
| 流式协议 | 随机验证码回显，检查 SSE JSON、协议事件顺序及正常结束 |
| 非流式协议 | 明确请求 JSON 响应，检查完整响应及随机验证码 |
| 工具调用与结果回传 | 强制调用本地定义的工具，校验随机参数，再回传新生成的回执，核对最终回答；不执行模型指定的代码或外部工具 |
| 结构化输出 | 发送各协议原生 JSON Schema 参数，校验精确的字段、类型与随机值 |
| 随机推理题 | 快速 2 题、完整 4 题，内置随机客观题，本地判题，不发送标准答案 |
| 速度与连续请求 | 快速 2 次、完整 5 次顺序请求，展示首字延迟中位数及按上游用量计算的输出速度 |
| 缓存验证 | 1 次预热、2 次变更后缀的验证，仅后两次计入缓存比例；缺字段为无法判断，零命中为未观察到命中 |
| 长文本检索 | 快速约 8 KB、完整约 32 KB，在参考文本中间放置随机目标，核对检索结果 |
| 图片识别 | 本地生成随机红蓝方块 PNG，按像素生成标准计数，通过原生图片输入检验，报告保留原图 |

Codex OAuth 的原生端点使用流式协议，非流式、工具回传和结构化输出项目当前显示不支持，不伪装执行。其他上游拒绝功能参数时会保留状态与允许展示的参数名；超时、截断、连接错误记未完成，不记能力答错。

报告逐项显示通过、异常、未完成、不支持、无法判断、未观察到命中，保留题目、原始回答、工具调用、耗时、上游报告模型与用量、配置指纹。可重新打开查看最近 60 份该目标的检验报告，并导出 JSON。浏览器关闭不取消已排队的任务；网络失败不自动重发付费请求。执行前后复核账号凭据、路由和请求配置，变更则停止并标记，避免混合结果。

结果仅说明当前样本中的功能兼容和表现：上游模型名称、token 用量都可由上游自报，不能证明官方来源、真实模型身份或计费真实性。短时速度采样不代表全天稳定性，32 KB 检索不代表验证了模型最大上下文。没有接入 CCTest 第三方服务，也不把账号密钥或检测报告发送给它；不提供没有可信验证基础的模型身份或签名认证结论。

部署自动运行新增迁移 `251_channel_inspection.sql`，仅扩展质量监控任务类型及检验配置，不改账号和用户账单。数据库测试可运行 `QUALITY_TEST_DATABASE_URL=... go test -tags=integration -race ./internal/quality`；前端新增 `src/features/quality/__tests__/ChannelInspection.spec.ts`。

### 自定义问题

在“渠道检验”中勾选“加入自定义问题”，可与内置项目一起运行，也可取消全部内置项目，仅运行自己的题目。每轮最多 8 题，每题一次真实请求，开始前计入请求数；每题问题最多 4000 字、参考答案最多 1000 字，整组文字最多 24 KB。

- 精确匹配：忽略回答和答案两端空白后，按大小写比较全文。
- 包含全部关键词：每行一个关键词，回答需包含所有非空行，区分大小写。
- 人工查看：允许任意开放题，保存原始回答和可选参考说明，显示待复核，不自动算通过或答错。

标准答案、关键词和评审说明只保留在本站，不发送给上游；只发送问题正文。回答按纯文本展示。自动判定只比较文本，不使用裁判模型，也不执行返回内容。可在“检测设置”的“自定义问题”中保存常用题目，再于检验窗口载入；本轮编辑不覆盖常用题目。常用题目保存在已有 settings JSON，任务单独保存当时的题目和判定规则，修改模板不改变旧报告或已提交任务。开放题不参与原有定时整数题库。

### 外部测评入口

工具栏“外部测评”无需先配置检测账号即可打开，提供 CCTest、okTest、真测 Ztest、LLM Test 和 Artificial Analysis 的介绍与跳转，覆盖 GPT / ChatGPT 和 Claude。前四项用于交叉参考渠道检测，Artificial Analysis 是模型能力、速度和成本的公开基准，不直接检验本站配置的渠道。介绍参考 2026-11-04 各站公开说明，实际支持以对方页面为准，未将宣传结论当作官方认证。

链接在新窗口打开，不附带本站 Key、账号信息、报告或来源页；第三方工具需自行配置测试信息。建议使用低额度临时 Key。本站不调用第三方检测接口，不因打开链接自动发送收费请求。
