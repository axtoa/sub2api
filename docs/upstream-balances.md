# 上游余额（管理员）

入口为「小账本」下方的「上游余额」，在当前控制台 `/admin/upstream-balances` 打开，使用真实管理员鉴权。

## 钱包不是 Key

一个上游登录账户的多个 Key 可以共用钱包：只建立一个钱包，关联所有使用它的本地账号，选一个 API Key 账号作为查询来源。域名不能证明钱包身份，需管理员自行确认。同一域名下的独立账户须分开配置。每个本地账号只能关联一个钱包，避免重复统计；不同 Key 是否属于同一上游账户不能自动可靠判断。

自动模式使用现有账号中的 API Key、base_url 和代理。Sub2API 模式固定 GET `base_url/v1/usage`（已有 `/v1` 不重复拼接）；New API 模式固定 GET `base_url/api/usage/token/`（去掉末尾 `/v1`，保留 New API 路由要求的末尾斜杠）。新查询要求 HTTPS，应用出站白名单，默认阻止私网目标和私网 DNS 解析；只有运营者明确启用私网白名单策略时允许私网。禁止跟随重定向，不执行模型请求，不复制或向前端返回密钥，不保存上游登录密码，也不接受任意脚本。

Sub2API 各版本/二开并不保证接口兼容。自动模式辨别 `wallet` 钱包余额、`key_quota` Key 限额、`subscription` 套餐周期额度，只有明确的钱包余额才能加入实查资金汇总。只有速率窗口或未知响应不能推测成钱包余额；没有单位也不猜成美元。不支持时改手动记录。

New API 默认复用所选账号的模型 Key，无需额外凭据。上游令牌启用“允许查询用户额度”后，优先使用 `data.user_quota.total_available` 作为钱包余额；否则 `data.total_available` 只作为 Key 限额，不进入实查钱包汇总。无限额 Key 没有钱包字段时显示无法查询钱包，不记为零或无限余额。每美元额度单位默认 500,000，可按上游实际配置调整（1–1,000,000,000,000），使用十进制精确换算，单位固定 USD。调整换算比例使旧快照失效，须重新查询。旧版不支持该接口或不允许查询用户额度时，可尝试下述账户方式或继续手动记录余额。

### New API 可选账户访问令牌

编辑 New API 钱包，展开“账户余额查询（可选高级配置）”，默认仍使用已有模型 Key。若该上游未提供令牌查询账户额度的功能，可选择“账户访问令牌”，填入上游个人设置签发的 Access Token；部分版本还需用户 ID，留空时不发送 `New-Api-User`。用户 ID 是上游账户 ID，不是模型 Key 编号。凭据权限与接口支持取决于上游版本，本站不能把拥有管理权限的令牌降为只读令牌。

账户方式只发送 GET `base_url/api/user/self`，读取 `data.quota`，按同一每美元单位精确换算，并校验已配置的用户 ID 与返回 ID 一致；不发送模型请求，不自动登录、不存密码或浏览器会话，不自动尝试其他凭据或地址。不支持时保留错误及同一来源上次成功值。可点击“保存并查询”验证，普通“保存”不会额外触发立即查询，定时查询仍受原开关和周期控制。Sub2API 和手动模式不展示账户令牌配置。

访问令牌是仅写字段 `newapi_access_token`：省略保留，非空替换，空字符串清除。响应只返回 `newapi_has_access_token` 布尔值，不返回令牌、掩码片段或密文。界面用密码输入框，关闭后清空草稿，不写浏览器持久存储；明确清除时切回模型 Key 查询，切到非 New API 模式也会删除密文。审计中间件完全省略钱包保存请求体（包括无效 JSON），钱包历史只保存配置与是否已配置凭据。幂等响应中不保存明文或密文。

服务端复用既有 AES-256-GCM 加密器，密文单独存于 `upstream_wallets.access_token_encrypted`，不在 config JSON。必须提供固定的 `TOTP_ENCRYPTION_KEY`（32 字节、64 个十六进制字符）或配置 `totp.encryption_key`，自动生成的进程临时密钥不启用此功能；`credential_storage_available` 会反映可用状态。密钥须通过部署环境或独立配置提供，与数据库分别备份，各实例使用同一固定密钥。切勿在已有加密数据的部署中随意更换密钥。未配置固定密钥不影响模型 Key 查询、Sub2API 或其他余额功能。

加密内容绑定钱包 ID、查询来源账号、上游地址和代理路径，禁止将数据库中另一钱包的密文挪用；更改来源、地址或代理后阻止发送旧令牌，须重新填写。仅轮换同一地址的模型 Key 不要求替换账户令牌。钱包版本及查询租约阻止在途旧查询覆盖新凭据配置。现有 HTTPS、出站校验、私网限制、禁重定向、超时和响应大小限制仍适用。此保护不能抵御应用服务器被完全控制或上游自身泄露凭据；优先配置权限最小的令牌。

迁移 `252_upstream_wallet_credentials.sql` 只新增该密文列。回滚程序时保留列，避免丢失配置；旧版不会使用账户访问令牌方式，不应依赖它继续查询该方式的钱包。

排查时先区分保存失败与查询失败：保存钱包返回“请求格式无效”且后端仍为旧版本时，需更新并重启对应本地服务，保证它识别新的字段；这时尚未请求上游。保存成功但查询报 `wallet_quota_unavailable`，表示上游返回无限额 Key 且没有账户余额字段。如果上游提供“允许查询用户额度”则开启后重查；没有该功能时，可使用上述账户访问令牌方式。若两种接口都不支持，应使用手动记录，不能将无限额 Key 当作钱包余额。

默认查询周期 30 分钟，可设置 5–1440 分钟并单独关闭。立即查询和全部查询不受自动开关、周期或失败退避限制，但保留鉴权、每实例最多三条并发，以及钱包级数据库租约（防止多实例同时查询）。编辑钱包使在途查询失效。网络请求最长 12 秒，响应限 512 KiB，错误仅存稳定原因码；不保存原始响应或 URL 中的机密。

失败保留同一来源上次成功值，显示失败/过时，不把失败记为零。成功值超过两倍查询周期即过时。修改密钥、地址、代理关联或来源账号后，旧来源的值不再展示。过时值不进入实查汇总，也不用于预计可用天数和邮件提醒。

## 消耗与估算

只读现有 `usage_logs`，用历史 `COALESCE(account_stats_cost,total_cost) × COALESCE(account_rate_multiplier,1)` 的账号侧成本快照，展示今日（应用时区）、近七天（滚动 168 小时）、本月以及每个关联账号的分项。卡片成本标题右侧以小字显示累计消费（USD），汇总当前关联账号接入本站以来的全部现存历史记录，包含建立钱包之前及超过 90 天的记录；无消费或未关联账号时为零。不用用户侧 `actual_cost` 作为上游成本，不改现有价格、倍率、余额、日志或调度状态。

手动钱包可只记录余额、不关联账号。USD 且关联账号时可选择估算：校准余额减去校准时刻后本站账号成本。新建或切换模式、币种、关联账号时须重新校准，充值后可再次校准。实查余额不再减本站消耗，避免重复扣减。币种不同不换汇、不相加；Key 限额和套餐不计入钱包总额。手动/估算值也不混入实查汇总。

按近七天日均消耗估算可用天数；无消耗、非 USD、套餐/Key 限额、过时或不完整记录不推算。账号缺失或估算基准超过 90 天时暂停估算，要求核对及重新校准。估算日志最多回看 90 天，累计消费读取全部现存历史；使用现有账号/时间索引，一次只读一致性事务，8 秒超时；前台每分钟更新且隐藏页面暂停轮询。

本站成本并非上游账单的保证值。上游调价、外部使用、成本配置误差、日志清理及延迟入库都会导致偏差；历史日志无法凭空补全，估算仅作参考。分项显示与总计四舍五入可能有末位微小差异。

## 低余额提醒

每钱包可设置阈值，页面标色。邮件默认关闭，手动开启并配置最多五个邮箱后复用系统 SMTP。仅对不陈旧、数据完整的低余额记录提醒，保留钱包/Key/套餐/手动来源标签。按应用时区每邮箱每天最多一封摘要，发送前在数据库领取，避免多实例重复发送；失败或未确认当日不重发，次日重试，设置中可见近期状态。SMTP 与数据库不可组成原子事务，极端情况下次日可能重复通知。

不自动充值，不自动切换、暂停或删除账号，不创建小账本收支流水。

## 一致性与部署

仅新增独立 `upstream_wallet_*` 表，无既有业务表结构修改。配置与校准使用版本冲突检测、UUID 幂等编号、事务及审计记录，响应丢失可使用同一请求编号重试。查询快照不递增配置版本，但受配置版本、租约和来源指纹保护。所有接口禁止缓存。

部署自动执行迁移 `247_upstream_balance.sql`。应用回滚保留这些表即可，不为回滚删除余额记录。预览数据不应导入生产。

## 故障隔离

余额模块使用独立 PostgreSQL 小连接池（每实例最多两条连接、无闲置连接），不使用小账本/网关的 SQL 池执行扫描和写入；只在读取现有账号配置时短暂复用现有仓库。独立连接具有 3 秒连接、8 秒语句、2 秒锁等待超时；接口总时限 25 秒，单次查询总时限 20 秒，后台轮次最多 3 分钟。关闭模块只关闭它自己拥有的连接池，不关闭主数据库。

初始化失败只禁用余额接口，不阻断应用启动；请求、后台轮次、各个查询任务均在模块边界隔离 panic，不记录可能含密钥的 panic 内容。单钱包上游探测异常会记录稳定错误码并释放查询租约，其他钱包继续运行。余额表缺失、查询/邮件失败仅令本模块报错，不调用小账本，不写入任何现有业务表。

这是同进程、同 PostgreSQL 实例内的故障保护，不是基础设施级硬隔离：数据库整体不可用、进程 OOM 等仍会影响所有功能。首次部署仍须经过现有全局迁移校验；不为可选功能静默跳过迁移失败。

PostgreSQL 并发/事务测试：设置专用本地 `UPSTREAM_BALANCE_TEST_DATABASE_URL`，执行 `go test -tags=integration -race ./internal/upstreambalance`。仅创建并清理测试自己的临时 schema，探测与 SMTP 使用测试替身，不向真实上游发送密钥或产生模型消费。
