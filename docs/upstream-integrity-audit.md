# 上游用量、计费与模型一致性审计方案

状态：2026-11-05 已实现首版评估面板与审计入口，下方保留完整设计目标，文末逐项说明当前范围与限制。实现验证使用模拟响应和一次性数据库，未运行真实渠道对照或付费请求。

## 已确认的需求

官方 API 参照、可信中转参照均为选填。支持同时保存多个参照，以后补上官方 Key 时不需要重建任务；没有参照也能运行基础检查。参照还应支持历史可信报告、手工导入的计数样本。不同来源分开展示，不能把“管理员指定为可信”写成官方认证。

检测需要回答三件不同的事：请求是否被额外添加内容；上报 token 是否与可复核的请求、响应相符；实际扣款是否符合约定。模型替换、混用和参数降级另设证据与统计，不通过一道题或模型自述判定身份。

## 方案制定时的能力与缺口（2026-11-04）

现有“渠道检验”具备流式/非流式、工具调用与结果回传、结构化输出、随机推理题、短时速度、缓存、长文本检索、图片和自定义题检查。报告保存回答、上游声明模型、输入/输出/缓存 token、状态和耗时。捕获用量发生在本站计费规则调整之前。

当前缺少：最终发送请求的可复核快照或规范化标识；官方/可信参照的配对请求；独立推理用量；实付账单核对；多批次模型表现漂移分析。因此现在不能给出可靠的注入比例或真实低价模型混用比例。

需先隔离本站自己的开销：当前检测复用连接测试传输，Anthropic 路径保留 Claude Code 系统提示，部分 OpenAI 路径使用默认 instructions，并沿用账号模型映射。只按题目正文计数，会把本站已知提示误认为上游注入。新审计应提供 API Key 下的受控最小请求及实际业务请求两种配置，分别统计本站可见的附加内容。OAuth 原生请求无法与普通 API 请求完全对齐时，保留结果但不给出直接可比的超量结论。

代码依据：`backend/internal/service/account_quality_probe.go`、`account_test_service.go`、`backend/internal/quality/inspection.go`、`runner.go`。

## 四档可选参照

| 条件 | 可以输出 | 不能据此确认 |
| --- | --- | --- |
| 无外部参照 | 用量缺失/不合法、重复请求稳定性、不同输入长度的增长趋势、答案正确率、缓存行为；已知 tokenizer 下的可见文本估算 | 精确注入量、计费是否诚实、模型真实身份 |
| 一个或多个可信中转 | 同请求对照、各参照的输入差异、能力和速度分布、参照间冲突 | 哪个参照一定正确；共同上游或共同误报不能互相证明 |
| 官方计数或官方 API | 同模型版本、协议和完整输入的计数/生成对照；区分估计计数与实际生成用量 | 隐藏注入内容、另一渠道实际调用了哪个模型 |
| 可关联的实际账单 | 约定价格与实扣的差异、缓存折扣是否兑现、重复收费 | 单靠余额差推断单次请求扣费；并发、延迟入账和舍入需先排除 |

历史或导入参照必须记录模型版本、协议、完整请求标识、参数、计数口径、日期和来源。请求变了、版本变了或资料不全时，显示不可直接比较，不填 0，也不自动复用过期参照。参考账号使用已有账号管理保存凭据，审计配置仅保存账号引用、模型、来源类别和备注，不新建明文 Key 字段。

同一次任务可以选择多个参照，先限制同时使用数量并明确展示总请求量；保存库可以有更多候选。参照失败只影响该参照的结论，主渠道和其他参照已有证据继续保留；不得悄悄切换到另一个参照、重试付费请求或把无参照结果标为通过。后续补充新参照只产生新的对照报告，旧报告不被改写。

## 用量审计

分别检查输入、可见输出、推理、缓存读取、缓存写入、工具与媒体用量，不能只比较 total_tokens。使用厂商、协议与模型版本对应的口径：例如 OpenAI 的缓存输入通常是输入总量中的子项，Anthropic 原生的非缓存输入、缓存读取和缓存写入分别列出，不能双重计入。兼容协议若改写字段，记录其适配规则；无法确认时不强行换算。

基础实验使用短、中、长三组受控输入，每组重复，回答要求短而可验证。变更随机标记与输入内容，覆盖中文、英文、代码和多轮场景；先以短纯文本建立基线，再逐步扩展工具、长上下文和媒体，避免把这些额外费用混在最初结果里。

在模型版本、协议、消息、system/instructions、工具定义、思考设置、缓存、输出限制等可比较时，分别展示每个参照：

- 额外输入量 = 渠道上报输入 − 参照输入。
- 相对参照的超量率 = 额外输入量 / 参照输入；参照为 0 或未知时不计算。
- 额外量占上报比例 = 额外输入量 / 渠道上报输入；上报为 0 或未知时不计算。

例如 1000 对 1500，表示相对参照多 50%，额外部分占上报 33.3%。界面名称应为“输入用量差异”，不能把它直接写成“已确认注入 50%”。保留负差异，帮助发现历史裁剪、压缩或用量漏报，不能统一截为零。

多长度样本拟合“固定附加量”和“随长度增长的差异”，展示有效样本数、残差和适用范围。这是诊断线索，不是作弊分类器：固定差异可能来自额外系统提示，比例差异也可能来自不同 tokenizer 或协议适配。仅在可比且有足够样本时输出拟合；小样本、基线冲突、截断和用量缺失时降低结论强度。阈值应经可信样本校准，不将固定百分比包装为通用造假标准。

输出审计必须考虑隐藏推理、工具参数、格式 token 和媒体。不能按回答字符数或可见文本估算值直接判定虚增，也不能把流式 chunk 数当成 token 数。即使响应提供 reasoning/thinking 明细，也标记为上游自报；缺少明细不等于推理为零。

## 计费与实际成本

分别保存上游原始用量、按约定价格计算的应扣金额、上游可关联账单的实扣金额。价格记录模型、输入/输出/缓存单价、长上下文阶梯、工具/媒体附加费、币种、余额单位和折扣，不能只保存一个倍率。

相同计价口径下，超量可能放大表面倍率，例如全部相关用量高 50% 时，0.3 倍可能表现为约 0.45 倍；实际混合成本仍须按输入、输出和缓存各自权重计算。报告重点展示“相同任务、达到目标质量后的有效成本”，并计算失败、重试的成本。

优先使用专用测试 Key 与请求级账单，通过请求标识、账号和时间核对。余额前后差只能作为粗粒度备用证据：需排除并发扣款、充值、退款、延迟入账、余额单位和精度问题；无法隔离时不声称是本次测试的准确费用。现有余额查询不等于已有请求级账单审计。

## 模型替换、混用与能力漂移

用多类客观可评分题和用户自定义题做跨渠道配对，覆盖推理、代码、工具回传、结构化输出、长上下文检索和多模态。优先选经可信参照校准、对目标模型有区分度的题目，随机化内容，保留标准答案在本站，不依赖“你是什么模型”、文风或上游 model 字段。

对同一账号、模型、分组分别保存多批次分数、失败类型、延迟与速度分布，覆盖不同时段和受控并发。与各参照及本渠道历史比较，发现突然变差、表现分群、工具支持忽有忽无、长输入失效等现象。样本需区分网络/限流失败、输出截断、拒答、自动判题限制和真实答错。

可输出“本次异常样本 4/20”“相对参照正确率下降”等观察，但不能称为“20% 廉价模型”。测试样本的异常率、线上流量的异常率和真实路由混用比例是三个不同的量。模型本身的随机性、题目难度和参照误差都会影响结果；从黑盒 API 通常无法认证真实模型身份或精确混用率。响应头、指纹或不透明签名也不能直接等同于可独立验证的官方认证。

## 其他应补的检查

1. 参数是否生效：思考强度、输出上限、工具约束、结构化输出等，通过可观测行为和协议结果验证；参数被接受不等于被执行。
2. 上下文是否被裁剪：多位置随机检索、多轮事实回忆，区分失败长度与完整上下文支持承诺。
3. 缓存是否兑现：冷启动、重复前缀、变更前缀分别测，既看命中上报，也看有条件可获得的实际费用。
4. 历史答案回放：随机 nonce 和动态题防止只返回旧答案；真实 prompt cache 不等于答案缓存造假。
5. 流式质量：响应顺序、首字、正文到达节奏、结束标志、截断与中断；假流式影响体验，也不能仅凭节奏断言模型真假。
6. 重试和失败计费：客户端/本站/上游各层请求尝试分开统计；记录无法确认是否执行的超时，避免测试自动重发造成重复扣费。
7. 持续退化：按账号、模型和分组看历史，区分高峰限流与长期能力下降。单次通过不意味着后续一直正常。
8. 下游体验：用本站真实的多轮与工具工作流补充最小探针，识别“测活能过、真实任务失败”的渠道。

## 落地顺序与验收

第一步是补齐证据记录和可选参照管理：不改变现有检测计划，允许没有参照，复用安全凭据保存及账号并发槽。请求证据记录最终模型映射、协议、参数、可见附加提示、规范化请求标识、响应完成情况和原始用量摘要。避免保存认证头、Cookie 或凭据；请求快照只包含合成测试数据，敏感配置默认仅存脱敏标识。

第二步增加“用量与计费审计”：基础用量检查、同请求多参照、重复与长度实验、缺失口径说明、逐项差异和导出。官方计数作为可选能力，端点不支持或参照不可用时正常降级，不隐式替换。先出证据，再在校准后增加提醒阈值。

第三步增加“能力一致性与持续抽检”：复用题库，增加对照任务和历史分布，展示异常样本率、统计不确定性及题目覆盖；账单核对在取得可关联账单后单独接入。

所有真实请求手动启动并预览主渠道、每个参照、计数/缓存预热/复测各自的调用量。默认低预算、不无限重试，说明输出上限与 OAuth 原生限制，预留与实际确认用量分别记录。自动长期抽检另行配置明确预算，不因配置参照自动开始付费检测。

验收覆盖：无参照、单/多参照、官方后补、模型/协议不同、参照故障、基线为零、推理明细缺失、缓存口径、截断、配置变化、历史报告不变、版本冲突、并发实扣不可归因。自动测试使用模拟响应，不用真实付费 API 验证造假识别。

## 已实现范围（2026-11-05）

质量监控原有账号卡片、账户优先级顺序、题库、渠道检验、自动检测与外部资源全部保留，新增独立的“上游质量评估”面板，不改变业务路由。

### 评估与排名

- 六个维度：可用性、能力与一致性、协议与工具、首字延迟、输入用量一致性、计费符合度。
- 聊天默认权重依次为 25/25/20/10/10/10；Agent 为 25/20/30/5/10/10；成本用途为 20/20/10/5/20/25。可编辑一份指定用途的自定义规则，其余用途保留内置预设。
- 成功率维度使用 Wilson 95% 下界，避免 1/1 等同 100/100。延迟分为 min(100, 可接受 TTFT / 实测 P95 × 100)。对账分为 min(100, 应扣 / 实扣 × 100)，同币种、可归属记录分别计算后平均；这是计费符合度，不是绝对价格或性价比排名。
- 总分只对达到最低样本数的已测维度按权重归一，覆盖率单独展示。最低样本数依次为可用性规则值、能力 4、兼容 3、延迟 3、用量 6、对账 1。未知不填 0 或 100。
- 默认参与排名需至少 8 次实际请求、3 批检测、60 分钟观测跨度、60% 维度覆盖，必需能力至少两批有效检验。证据有效期默认 48 小时。历史窗口可选 1/7/30 天，过期项不混入当前得分。
- 仅对相同平台、请求模型、输出/思考/题数等设置以及已测维度集合分别排名。账号原卡片仍按管理优先级排列。分数 ≥85 显示表现较好，65–85 基本可用，低于 65 表现较差；证据不足、过期、待复核和触底线另外显示，不参与排名。
- 反复不可用达到默认 20% 且至少 3 次，必需能力两批失败或实际请求明确不支持，以及人工确认的模型交付/隐私问题、超过默认 2% 的已确认计费超额，独立标记底线。仅检测器不能表达原生功能的情况属于未知。普通慢响应、该用途选填能力失败属于可容忍扣分或功能限制；用量差异属于复核项。
- 按当前版本、账号配置和凭据身份指纹过滤旧证据。指纹只保存摘要，凭据不进入审计配置、请求指纹或报告。升级到 objective-v3 后旧报告仍可查看，但不参与新口径排名。
- 定时能力题有足够样本时，比较最近 24 小时与此前的正确率，各至少 20 题；置信区间不重叠的下降标记复核。改变题组的临时题不混入这一趋势。
- 读取评分最多每个目标 1000 条历史，超过时明确显示截断并停止排名；评分查询去除题目和回复正文。完成报告保留完整 30 天，有人工证据的报告继续保留供复核。

### 检测与参照

- 新项目默认不勾选，不扩大原快速/完整方案费用。用量审计为短、中、长输入各重复两次（6 请求）；能力一致性复用本地可验证的路径、条件汇总与异或优化题，各重复三次（9 请求）。题目由复现种子决定，标准答案不随题目发送。
- 保存最多 8 个已有账号模型参照，每次最多选 3 个，官方/可信/其他均为管理员标记。同一平台、同一请求模型才能选择，使用主检测的受控参数；参照失败或变化不影响其他渠道的已有证据。逐请求使用原有账号并发槽、预算和租约，付费请求不自动重试。
- API Key 下隔离连接测试的系统提示；OAuth/setup-token 保留必要原生配置并标记不可与受控 API 直接比较。实际 JSON 请求体记录 SHA-256 和字节数，捕获原始输入/输出/缓存及可选推理/total 明细。缺少推理明细保留未知。字段非法、缓存超过输入或推理超过输出等保留复核线索，不按正常已确认用量结算检测预算。
- 同完整请求指纹、协议、可控配置且两端报告完整合法用量时，展示正负输入差值、相对参照比例、差额占上报比例。默认需绝对差额超过 32 token 且相对差额超过 15% 才提示复核。重复请求检查不算外部参照，不能据此补满用量完整性得分。
- 每个参照至少 6 个可比样本、3 个不同输入长度时，拟合固定差额、增长差额及 RMSE，同时展示输入适用范围。这是差异诊断，不是作弊判定。
- 支持选择历史审计报告复用种子、对照当时原样本；支持保存最多 50 条带来源说明、日期、模型、协议和完整请求指纹的手工输入计数。手工计数 30 天内有效，仅匹配相同请求。旧报告保存当时的参照快照，新增或修改参照不改旧结论。
- 可按同模型分组主动选择最多 20 个账号统一检测，先显示费用请求数，再由管理员确认。批量默认无外部参照，逐账号检验可选参照。打开、刷新、编辑规则或保存参照不会调用模型；一个批次不会自动满足多批次证据要求。

### 对账与人工证据

管理员可在报告中追加实际计费、模型交付、隐私核验记录，保存依据、证据编号、操作人、时间。对账仅纳入本报告主账号的费用，排除参照账号，需明确币种、应扣/实扣及可归属声明；金额由管理员根据约定价格、缓存、折扣和附加费核算，不用并发钱包差额自动推断。

记录只追加，最新的同报告同类别结论用于评分；修正需追加“已核对/已排除”并给出依据。已确认底线不会因报告超过评分有效期而自行消失。面板可直接打开对应历史报告继续复核。

### 实际边界

当前评分反映主动/定时探测的证据，不把 ops 错误日志当作完整真实流量分母。原有线上观察卡片继续提供业务参考。自动官方计数接口、各上游账单适配、媒体/工具附加费自动计算、受控并发压测与更大规模经校准的辨识题集仍需各自的数据与适配；可以先用手工参照和人工对账工作。

无法通过黑盒测试保证认证真实模型、精确注入内容或混用比例。当前重复题的异常次数、参考间分歧、能力下降和价格差异都应回到证据复核，不自动封禁、调价、停用或修改路由。
